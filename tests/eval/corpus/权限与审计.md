# 权限、审计与隐私边界

## 本机优先的威胁模型

这个产品的默认使用场景是单机：服务只监听 127.0.0.1，主要威胁来自同机的其它进程与误开的端口，
而不是互联网上的攻击者。因此安全策略围绕「默认收紧、显式放开」设计。

## 密钥与角色

访问凭据是 API Key，库里只存哈希与前缀，不存明文。角色分读者与写者两种：
读者可以调用检索、列表、统计这类只读方法；写者才能改数据、合并实体、改任务状态。
权限不足时返回 403 而不是 500，让调用方知道是权限问题而不是服务故障。

## 审计

每次写入都会落一条审计记录，包含操作者、动作、资源类型与资源 id、结果状态。
审计日志是排查「这条数据是谁改的」的唯一依据，所以不允许静默写失败。

## 出域与隐私分级

语言模型默认不配置；配置后，送出去的上下文范围由出域策略决定，默认只允许当前文档或选中范围，
不做「默认全库上云」。每次出域都会写一条出域审计，记录范围、字符数与耗时。

## 落盘加密

整库加密列为可选能力，不做默认开启：开启后忘记口令等于数据不可读，
对单机用户来说风险高于收益。密钥材料只存在主进程，渲染进程永远拿不到明文。
