# 检索评测方法

## 先说结论：没有基线就没有优化

评测集是「优化」这件事的前提。没有固定问题集，任何一次调参都只能靠感觉，
而感觉在检索这种多变量系统里几乎必然出错。

## 指标定义

- recall@k：期望命中的文档（等级大于等于 2）中，有多少出现在前 k 条结果里。k 取 1、3、5、10。
- MRR：第一条相关结果名次的倒数，再对全部问题取平均；同一问题里有「必须命中」等级时优先看它。
- nDCG@k：用相关性等级加权的折扣累计增益，用来比较排序质量而不只是看召回。
- 块级命中率：结果里带回的块正文是否包含期望的关键片段。

## 数据集划分

问题集分成 dev 与 holdout 两部分：dev 可以反复看、可以拿来调参；holdout 只在发版前跑，
不参与任何调参决策。基线文件同时记录两者的分数，但只有 holdout 作为门槛，
下降超过阈值就返回非零退出码。

## 防过拟合的具体做法

- 评测脚本禁用随机性：向量索引的 k-means 初始化使用固定种子，避免「换一次随机初始化」与
  「换一次参数」分不清是谁带来的差异。
- 语料覆盖多种格式与两种语言，避免得出「分词器对某一种语言友好」这类单一结论。
- 报告按检索模式与标签分桶，否则平均值会掩盖「语义类问题全崩」这种关键信息。
- 同时看 recall 与 MRR：只优化召回会得到一堆排不上来的结果。

## 语料规模约束

语料控制在五十到两百篇、总量二十兆以内，保证单次全量评测能在几分钟内跑完，
否则评测会因为太慢而被跳过，跳过等于没有。
