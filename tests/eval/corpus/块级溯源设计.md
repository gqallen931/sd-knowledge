# 块级溯源设计（chunks 表）

## 为什么需要块

`vectors` 表原本只有 `document_id`，没有块序号、没有字符偏移、没有页码。
检索能给用户「是哪一篇文档」，却给不出「文档里的哪一段」，问答引用也就无法点回原文位置。

## chunks 的字段口径

块表记录文档 id、文档内块序号、块正文、起止偏移、锚点类型与锚点值、音视频时间戳、token 估算值，
以及生成本块时的分块参数快照（chunk_size 与 chunk_overlap）。块序号从 0 开始，与向量表的块序号一致。

字符偏移相对**归一化后的**正文：写入正文时统一把 `\r\n` 换成 `\n`，块的偏移也基于同一份文本，
否则偏移会整体错位。这是实现时必须锁死的细节。

## 七种格式的锚点来源

| 格式 | 锚点类型 | 来源 | 精度 |
|---|---|---|---|
| PDF | page | 逐页累加文本时记录每页的起止偏移 | 页级 |
| PPTX | slide | 按幻灯片文件名数字序拼装文本 | 幻灯片级 |
| EPUB | chapter | 按 OPF 的 spine 顺序逐章抽取 | 章节级 |
| XLSX / XLS | sheet | 按工作表分节拼装，锚点值是工作表序号 | 工作表级 |
| 音频 | time | 转写分段的起止秒数 | 秒级 |
| 视频 | time | 关键帧时间戳 | 帧级 |
| 图片 / 扫描件 | page 加 bbox | OCR 文本块坐标 | 块级 |

给不出锚点的格式（纯文本、Word、CSV）返回空数组，**不编造**编码类型的页码。

## 两种回填路径与取舍

- **P-a 确定性重建（采纳）**：对每篇已有正文的文档，用与解析时相同的分块函数从正文重建块，
  锚点尽量取自解析时落库的元数据；随后重新推理向量并整体替换该文档的向量行。
  精确性高，代价是全库重嵌入（向量推理约占文档处理耗时的七成）。
- **P-b 插入序启发式（默认关闭）**：按向量 id 升序与块序号对齐。便宜，但依赖写入顺序，
  历史库一旦经历过重解析或复用就会错位，而且错位无法被检测，所以不作为默认行为。

回填的幂等键是「该文档是否已有块」；写入顺序是「先建新块、推理成功后再删旧向量」，
推理失败时旧向量保持不动，文档仍可语义检索，只是暂时给不出可定位出处。
