# 混合检索设计（RRF）

## 为什么不再串行回退

改造前的检索是「全文零命中才试语义」：只要全文有任意一条命中，语义结果就完全不参与排序。
这不叫混合检索——它会让一次偶然的字面命中把整条语义召回挡掉，也让全文结果只能按导入时间排序。

## RRF 公式与常数

全文通道（FTS5 trigram）给出 rank_ft，向量通道（内存 IVF）给出 rank_vec，两路按倒数排名融合：

    rrf(x) = w_fulltext / (k + rank_ft(x)) + w_semantic / (k + rank_vec(x))

常数 k=60 是业界经验值，作用是压制头部名次之间的差距：它让「两路都排第三」优于
「一路第一、另一路完全没命中」，避免单一通道的偶然高分直接决定最终名次。
通道权重默认都是 1.0，可在设置里调到 0 到 3 之间。

## 融合粒度

检索阶段在文档粒度融合：FTS5 只提供文档级命中，向量通道把同一个文档的多个块归并到最高分那一块。
展示阶段再回到块粒度：每个入选文档取出分最高的块作为摘录，并带上该块的可定位出处。
若直接按块粒度对齐，全文通道会恒定缺一块，权重就失真了。

## 规则重排系数

最终得分 = rrf × (1 + α·recency + β·scope_match + γ·type_match + δ·entity_overlap + ε·title_hit)

- α=0.15 时间新近度，半衰期 30 天；权重被硬限制在 0.2 以内，防止「最近导入的总是赢」
- β=0.10 作用域命中：精确落在指定目录或项目内为 1，落在其父目录为 0.5
- γ=0.05 文件类型匹配，例如查询里显式写了 pdf
- δ=0.05 查询实体与文档实体的重合比例
- ε=0.20 标题命中，是最强的单条信号

五个系数之和被限制在 1.0 以内。全部重排都只靠规则，不引入外部 rerank 模型。

## 截断语义

结果信封里的 truncated_reason 有四种取值：limit 表示命中数超过上限属正常截断；
candidate_window 表示语义候选窗口已用尽、结果可能不完整；scope_filter 表示按作用域过滤后候选耗尽，
也就是限定范围可能导致漏召回；token_budget 表示上下文超预算只带了一部分段落。
不允许乐观地报 truncated=false：只要候选窗口耗尽或作用域过滤耗尽了候选，就必须如实标注。
